# Architecture decisions

Each decision names what it was chosen over and what would change it. "Provisional" means a Phase 2/3 measurement can still overturn it.

## D1. Frame-synchronous system: one emulator frame = one SNN time step
Emulated events carry one timestamp per frame (D3), so there is no finer time structure for the SNN to use on Track B. The network therefore steps once per frame (bin = 33,333 us = one 30 fps frame). Track A events are binned to the same 33,333 us so both tracks feed the same network with the same temporal scale. Chosen over 5-10 ms bins (roadmap 3.1) because shorter bins would make Track A and Track B statistically different.
Changes if: Track A accuracy at 33 ms bins is much worse than at 10 ms. Then add a second training run and accept that Track B uses coarser bins.

## D2. Emulator: at most one event per pixel per frame, reference moves by theta ("step") - provisional
Matches `model/emulator_int.py` and the RTL. A large brightness change spreads over several frames (one event per theta of contrast per frame), which is the event-rate-limited behaviour of a real pixel. "reset" (reference = current value) is implemented as a CSR option and is bit-exact verified too. The float reference (`emulator_ref.py`) emits several events per pixel per frame like v2e. Roadmap 2.6/2.7 decides the default from the v2e comparison.
Changes if: v2e comparison shows step mode lags visibly on fast motion.

## D3. Timestamps: per-frame only (roadmap 2.5, option a)
`ts = (frame_index * period_ticks) mod 2^17`, tick = 100 us (17 bits wrap every 13.1 s), `period_ticks` from a CSR (333 for 30 fps). Interpolating timestamps inside the frame (option b) costs a divider or LUT per event and buys nothing while the SNN steps once per frame. It stays a stretch goal.

## D4. Time-bin boundaries are explicit markers, not timestamp compares
The bin accumulator closes a bin on an end-of-frame marker from the emulator (Track B) or from the HPS replay engine (Track A). Avoids the 33.33 ms vs power-of-two tick mismatch and any wrap logic.

## D5. SNN input: 2 x 32 x 32 binary maps
128x128 -> 32x32 by 4x4 presence (OR) per polarity (`model/snn_input.py`). Binary input means layer 1 needs adders only. State and weights are tiny (see `SNNConfig.sizes()`): conv1 144 weights, conv2 1,152, fc 11,264 (int8), membrane 8,192 + 4,096 + 11 words of 12 bit, about 150 kbit, well inside the 5.5 Mbit of M10K.

## D6. Neuron and quantization
`v -= v >> 4; v = clip(v + I, -2048, 2047); spike = v >= thr; v -= thr * spike` in the two conv layers, int8 weights, thr 64, no biases. **The output layer is not spiking**: each class accumulates its FC input current over the window and the argmax wins (readout "sum", see D10). The QAT forward pass in `train/snn_qat.py` runs this exact arithmetic on integer-valued float32, and `train/tests/test_qat_vs_int.py` proves it equals the numpy model bit for bit. Tie rule for the readout: lowest class index wins.
Surrogate gradient notes: (1) a boxcar surrogate has zero gradient for neurons resting at v = 0 and the toy network stalled at 50%; the fast-sigmoid shape with non-zero tails fixed it. (2) Its slope must be scaled by 1/thr because membranes are in integer units: with slope 1 the layer-1 weight gradient was about 10^6 and the output layer's about 10^-3 (exploding backward signal, about |w| per layer and step).

## D7. Hardware bring-up order: on-chip first, DMA second
The roadmap's HPS DDR3 DMA path (Phase 1.3-1.5) is the highest-risk item and the HPS image may only support C. So: (1) run the emulator and VGA event view from an on-chip pattern source and a small on-chip frame ROM, (2) then add the HPS path. HPS software is **C only**, with the PC doing video decode (the sister project's checklist section 5: a small C daemon owns `/dev/mem`, the PC talks to it over TCP/UDP). `sw/frame_feeder.py` runs on the PC and can write the byte image of the DDR3 frame ring (`docs/frame_buffer.md`).

## D8. Verification flow on this PC (Windows)
Roadmap said cocotb + Verilator on Fedora. Here: Icarus Verilog 14 (devel) and Questa FSE are installed, Verilator is not. The golden-model comparison is done with self-checking Verilog benches that read vectors generated by the Python golden models (`scripts/gen_emulator_vectors.py`), run by `scripts/run_regression.py` with the sister project's verdict rules and a mutation self-test (a deliberately broken RTL must fail). cocotb 2.1 is installed and can be added for the SNN core if Icarus-only benches become awkward. Bulk SNN regressions (5.10) will run in Icarus/Questa, or Verilator under WSL if simulation speed becomes the bottleneck.

## D9. Backpressure instead of drops
The emulator deasserts `pix_ready` when the event FIFO is within 8 entries of full, so a full-frame burst (16,384 events) stalls the pixel source instead of losing events. The FIFO still counts and flags any overflow (`err_flags[3]`, `ev_overflow_cnt`); it must stay 0.

## D10. Output layer: accumulate class currents instead of spiking (readout "sum")
First DVS128 Gesture runs with spiking output neurons sat at chance (9%) with loss above ln 11. Measured cause: with random weights each output neuron has a fixed sign, so it either fires on every step or never; the loss then pushes everything to the dead state, where the surrogate gradient is almost zero. Raising thresholds (finer weight resolution) did not help. A non-spiking readout (score[c] = sum over the window of the class-c FC current, argmax at the end) learned immediately: 56-70% training accuracy after 250 iterations in every setting tried. In hardware this is 11 signed accumulators instead of 11 LIF neurons, and the decision logic is unchanged (argmax, ties to the lowest index). The spike readout is still in the code (`SNNConfig.readout = "spike"`) and covered by the bit-exactness tests.
Also found on the way: DVS128 input is about 4x denser than the toy set (17% of the 32x32x2 cells active per step against 4%), so initial weights must be smaller than the toy-tuned ones (`--init-std 20,10,3`); check firing at init is 5-20% per layer.

## D11. Network size: 32x32 input with 16/32 channels (provisional)
Measured on DVS128 Gesture (`docs/results/trackA_accuracy.md`, "Network size study"): doubling the channels at 32x32 gains about 1.8 points over 8/16 on two seeds; 64x64 input gave no gain for about 3x the memory and 4x the layer-1 work. Memory is not the limit (13% of the M10K at 32x32 16/32); the limit is synaptic additions per 33 ms step, which the SNN RTL must be sized for.
Update 2026-10-27: regularisation (event dropout, mirror, speed, weight decay), 90-epoch training and a third conv layer (16/32/32 and 16/32/64) were all tried and none improved on 83% window / 90% sample beyond noise (`docs/results/trackA_accuracy.md`); the two-conv 16/32 network stays as the default because it is the simplest to build in RTL. A 3-conv 16/32/32 network is the alternative if weight memory ever matters (28% fewer weights, same accuracy, 1.6x more spikes).
Changes if: the own-clip domain-gap test (3.10) shows that small, fast hand motion is lost at 32x32, or a temporal-modelling change (longer memory, longer window) beats the plateau.

## D12. Dataset for the demo network: KTH actions on emulated events (2026-10-28)
The user asked for the project to be built around video, because video is much easier to get than DVS recordings. The network trained on real DVS128 Gesture events did not transfer to emulated KTH video (`docs/results/kth_domain_gap.md`), so the demo network is trained on KTH itself: 6 actions (walking, jogging, running, boxing, hand waving, hand clapping), whole 160x120 frame squashed to 128x128, 25 -> 30 fps by blending, the integer emulator at theta 0.20 ln (step mode) and the same 2x32x32 binning. Standard person split (train 11-18, validation 19-21 23-25 01 04, test 22 02 03 05-10). Decision window T = 32 bins (1.07 s) because the shortest repetitions (running) are about 1.9 s. DVS128 Gesture stays as the real-event reference (Track A). KTH is low resolution, indoor/outdoor, 4 conditions, 25 people; it is not a general gesture dataset and the demo claims nothing beyond it.

## D13. SNN inference engine: output-stationary, 8 output channels at a time, one 25 MHz clock (2026-10-28)
`rtl/snn_core.v` / `rtl/lif_conv.v`. For every neuron position the CIN*9 input bits are fetched one per clock and conditionally added (int8 weight) into 8 accumulators; leak, saturation, threshold and reset-by-subtraction are applied once per position and written back; spikes are OR-ed into the 2x2 pooled word. Rejected: event-driven (input-stationary) updates, which need read-modify-write on the membrane RAM and a separate leak pass; they would save cycles we do not need. Cost per step 205,832 clocks for 16/32 channels and 6 classes (8.2 ms at 25 MHz, a quarter of the 33 ms frame), so no second clock domain and no DSP blocks. Pooled outputs need no clearing sweep because the first neuron of every 2x2 block writes the word and the other three OR into it. The classifier accumulates the 6 class currents in 28-bit registers, argmax with ties to the lowest index (as `np.argmax`). Bit-exactness against `model/snn_int.py` is checked on every step, on both membrane RAMs after the last step, and on the window result (`tb/snn_core_tb.v`, `tb/snn_chain_tb.v`).

## D14. Board demo: replay of pre-binned real clips plus a live pattern chain (2026-10-28)
Storing real video frames on the chip does not fit (one 128x128 frame is 13 M10K, the clip would need 30 per second). The demo therefore has two sources (`SW[9]`): REPLAY plays 6 KTH clips that the Python emulator model already turned into 2x32x32 bins (64 steps each, 98 KB) into the SNN, which tests the SNN on real data on the board; LIVE runs the on-chip pattern source through the RTL emulator into the SNN, which tests the whole chain on the board but classifies a moving square (no meaningful class). Real video into the RTL emulator needs a host-written frame store; the proven mechanism is the JTAG-to-Avalon host bus (or the HPS TCP feeder) of `F:\Projects\FPGA-Thermal-NUC_Motion`.
